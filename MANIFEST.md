# Install Manifest — the target state of an enabled repo

> **Tool-operator-only** (like `UPGRADE.md` — never installed into a target). This file is
> the **declarative target state** that `ENABLE.md` converges a repo to (v4.35.0): every
> artifact the tool installs, as one row — target path, canonical source in this checkout,
> and the policy that governs it. The runnable **reconcile helper**
> (`scripts/reconcile.py` / `scripts/reconcile.mjs`) parses this file, diffs a target
> against it, and applies the mechanical policies; an agent without script execution can
> walk the tables by hand — each row is a complete instruction. Judgment work (analysis,
> seeding, migration, conflict arbitration) stays in `ENABLE.md`; version-gated data
> migrations live in **Semantic steps** below.
>
> **Machine-format contract:** the reconcile scripts parse the three sections below by
> their headings and table/list shapes. Keep the column order, keep cells free of `|` and
> backticks, and keep version cells as bare semver. Update this file **in the same commit**
> as any change to `templates/`, `agent-skills/` built-ins, `.githooks/`, the root protocol
> docs, or a rung that adds a non-mechanical step — then run
> `python3 scripts/reconcile.py --check-manifest` (release checklist, `UPGRADE.md`).

## Policies

- **verbatim** — the target file is a tool-owned, byte-identical copy of its source.
  Missing → copy; differs → **re-copy on apply** (drift is listed first in the dry-run —
  the warn-before-clobber arbitration in `ENABLE.md` §5i applies to a *customized* copy).
- **verbatim-dir** — like verbatim, applied to every file under the source directory
  (the tool-managed built-in skills). Extra target-side files are reported, never deleted.
- **seed-copy** — installed verbatim **only if absent**; an existing copy is **never
  touched** (it may carry user content — waivers, a team's own PR template, their CI root).
- **sentinel-merge** — managed blocks inside a user-owned file: add-only, de-duplicated
  against the whole file, never remove or reorder existing entries (`ENABLE.md` Step 7/7b).
- **seed-generate** — generated by the **agent** at enable (placeholders + judgment);
  never touched when present. The reconcile report points each at its `ENABLE.md` step.
- **stamp** — `.agent/version.md`: written by the agent as the **closing step**, after any
  semantic steps (never by the script — an early stamp would mask an unfinished upgrade).

`Forge` column: `all`, `github`, `gitlab`, or `azdo` (per `ENABLE.md` Step 4 detection).
Unknown forge → the `github` + `gitlab` rows apply; `azdo` installs only on positive
detection (its pipeline needs one-time activation — blind installs would just add noise).
`Attrs`: `exec` = must be executable (mode 755); `step:N` = the `ENABLE.md` step that
generates it; `wire` = when the file pre-exists, the agent wires it per `ENABLE.md` Step 6
(add-only include + stage check — never scripted); `renorm` = a merge here is followed by
`git add --renormalize .` (agent-run; check the staged diff stays within agent-memory
files on a CRLF repo); `-` = none.

Row notes (the table stays machine-lean; nuance lives here):

- **AGENTS.md** — the source is **always `templates/AGENTS.md`** (the target memory-protocol
  hub), never this tool's root `AGENTS.md` (the operator dispatcher). See `UPGRADE.md` →
  "Source of truth for re-synced files".
- **memory/sessions/** — "present" means the directory exists with at least one file; the
  first enable session log (Step 5c) is what normally satisfies it (`.gitkeep` only as a
  fallback when no log is written).
- **.gitlab-ci.yml** — seed-copy installs the canonical root file (include + the
  `workflow:rules` guard) only when the target has none. A pre-existing root file is never
  edited mechanically: the `wire` attr sends the agent to `ENABLE.md` Step 6 (add-only
  `include:` entry, mandatory stage check, never touch `workflow:rules`, state coverage).
- **Drift on verbatim rows** is expected on an older target (staleness, resolved by
  re-copy) but can also be a local customization — the dry-run lists every drifted file
  *before* apply so the agent can arbitrate (`ENABLE.md` §5i warn-before-clobber; a genuine
  fix should be upstreamed).

## Tool-only (never installed)

Everything in this checkout that is **not** a source in the table above stays
operator-side. In particular:

- ENABLE.md, MIGRATE.md, UPGRADE.md, MANIFEST.md, VERSION, README.md, CHANGELOG.md, LICENSE
- scripts/ (the reconcile helper + its tests)
- the root AGENTS.md, CLAUDE.md, GEMINI.md and root bootstrap dotfiles (this repo's own)
- agent-skills/hello-world/ (the tool's own skills-layer demo)
- memory/ (this repo's own dogfooded memory layer)
- docs/, examples/, mkdocs.yml, .github/workflows/docs.yml (docs site + design records)

`--check-manifest` verifies the complement: every file under `templates/`, `.githooks/`,
and the seven built-in skill directories is reachable as a row source (or listed here),
and every row's source exists.
