**The field incident (reported 2026-08-13):** a client repo's DLP scanner caught a **live OAuth
client secret** in a committed session log (log dated 2026-07-13) — an agent had pasted
smoke-test verification output verbatim, including a rendered kafka credential line. Session
logs and continuity are committed and shared *by design*, so nothing in the protocol or tooling
stood between a rendered credential and `git push`. The maintainer's directive: any secrets
(PII and credentials) must be redacted from session memory. The incident repo is client-side
(no direct access); their team handled rotation + history cleanup — this release closes the
loose end going forward. Immediate context also given to the maintainer at report time:
redaction alone is not un-leaking (git history + remote retain the original; rotation is the
real fix).

**The fix — doc rule first, observational lint second, never mutating** (the tool's established
escalation): 

- **Redaction rule in the after-session ritual** (`AGENTS.md` root + template, echoed in
  `ENABLE.md` Step 5c and the schema's session-file section): never write secrets or PII into
  `memory/`; redact pasted command/smoke-test output to `(REDACTED)` before persisting
  (template placeholders stay as-is — already safe); a secret that was committed anyway is
  **exposed** — rotate it; history cleanup is a separate, human-led step. Redaction is the one
  sanctioned edit to an otherwise-immutable session log.
- **`memory-lint` check (10) `[secret-material]`**, Python + Node at parity, mirror tests
  (44 each, all passing): known token shapes (AWS, GitHub, GitLab, Slack, Google, private-key
  blocks, JWTs), credential-key assignments with literal values (the rendered-JAAS class —
  placeholder forms, redaction markers, and number/date shapes recognized as safe), emails
  (public forms excluded), SSN and Luhn-verified payment-card shapes, and absolute home paths.
  Scans `memory/*.md`, `sessions/`, **and** `archive/` — the pasted-output surfaces check 7
  deliberately excludes. The report **never echoes the matched value** (a lint line quoting the
  secret would amplify the leak into terminals and CI logs). Advisory WARN; `--strict` /
  `AGENT_MEMORY_STRICT=1` gate it red; the existing CI floor picks it up with no forge-file
  changes. A `lint:allow-secret-material` tag on a line waives a deliberately-quoted example.
- **Dogfooded on this repo** (145 session logs + full archive): exactly two pre-existing
  `home-path` findings — old cleanup-audit logs quoting a mock path — and zero credential/PII
