## Adversarial pre-ship review — findings & dispositions

Both new YAML files parse; `memory-lint` errors 0. A 3-lens review workflow (GitLab tech with
web + source verification / protocol coherence / repo-wide claim sweep) ran over the staged
diff and earned its keep — **2 blockers, both fixed before commit**:

1. **`%{co_authored_by}` misprescription (BLOCKER → fixed everywhere).** Verified against
   GitLab's `message_generator.rb`: the variable is built from commit **author** fields and
   never parses body trailers — in this tool's own human-author + AI-trailer workflow it
   expands to *empty*. Guidance corrected (AGENTS ×2, MR template, getting-started, CHANGELOG,
   UPGRADE row + rung, thread, this log): primary = re-add the trailer when editing the squash
   message at merge; project-level lever = `%{all_commits}` (carries body trailers; dedup rule
   then applies).
2. **Missing-`stage:` hazard (BLOCKER → fixed).** The job uses GitLab's default `test` stage;
   an add-only include into a root defining custom `stages:` without `test` invalidates the
   target's ENTIRE pipeline config. The add-only path now mandates appending `test` to such a
   list (add-only; changes nothing about when their jobs run); hazard documented in the job
   header, ENABLE.md Step 6, and the rung.
