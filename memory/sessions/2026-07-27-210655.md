**Verdict: viable — meaningfully more viable than Bitbucket — with one honest asymmetry.**

What maps cleanly (better than either shipped forge in places):

- **PR template is a clean win:** `.azuredevops/pull_request_template.md` auto-applies to new
  PRs (default-branch-read; search order `.azuredevops/` → `.vsts/` → `docs/` → root;
  case-insensitive; markdown; 4000-char description cap; replaces the auto commit-message
  description).
- **Best advisory semantics of any forge:** `continueOnError: true` (step or job) yields a
  real tri-state — "partially succeeded" (orange) — plus `##vso[task.logissue type=warning]`
  annotations (GitHub-Actions-like). Build Validation policy itself also has a documented
  Required/**Optional** (notify-only) mode.
- **Two additive seams:** a repo can have **multiple pipelines, each bound to its own YAML**
  (an agent-memory job in `.azuredevops/agent-memory-ci.yml` touches nothing of theirs), and
  `- template: path.yml` local includes exist for teams preferring one pipeline (constraint:
  triggers must live in the main file). Base-SHA vars exist (`System.PullRequest.*`);
  default fetch is shallow=1 since sprint 209 → set `fetchDepth: 0`; ubuntu-latest has
  git + python3.

The asymmetry — **activation is not file-driven, twice**:

1. A pipeline is a **resource**: committing YAML does nothing until `az pipelines create
   --yml-path … --skip-first-run` (or UI New pipeline) binds it — one documented, scriptable,
   one-time step; default permission is **Contributors** (not admin-only). Once created, the
   implied CI trigger runs it on all pushes.
2. For Azure Repos the YAML `pr:` trigger is **ignored** — PR-time validation requires the
   **Build Validation branch policy** (Project Admin / Edit-policies permission — a settings
   change the tool must never make; documented as an optional human step).
3. Microsoft-hosted parallelism requires linking an Azure subscription (self-hosted tier is
   automatic) — honest limit; most real ADO orgs have this.

Attribution: same class as Bitbucket — squash drops trailers, no message template mechanism,
editable at merge; the PR-description footer (carried by the template) is the durable record.
Noted: the "Commit author email validation" policy checks the commit *author*, not body
trailers — agent co-author trailers are unaffected.
